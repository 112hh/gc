# 工程细胞主题库｜多组学分析原型业务功能说明书

> 版本：原型说明版（2026-08-09）  
> 适用对象：产品经理、工程细胞研究人员、数据管理员、生物信息人员、前后端研发与验收人员  
> 原型入口：[index.html](index.html)

## 1. 文档目的与范围

本说明书描述“工程细胞主题库—多组学分析”原型所表达的业务闭环、页面模块、字段、状态、角色权限及结果呈现原则。它用于统一产品设计和后续系统实现的边界，而不是复现脚本的操作手册。

系统面向工程菌、酵母等底盘细胞的多组学研究任务。用户将本次实验的样本、DNA、RNA、蛋白组、代谢组文件及对应参考资料登记到系统；经过数据审核后，系统依据任务实际数据条件生成可运行的分析模块；运行完成后，将每一步的输入、处理说明、输出文件、图件和结果保留在同一任务详情中，供下载、复核与后续工程验证使用。

本原型的真实结果展示来源于 `result_20260807`。复现包仅为产品设计提供文件格式、流程、输出结构和示例结果，**不应被理解为日常用户任务必须上传或固定使用的数据包**。

## 2. 业务目标与总体闭环

### 2.1 核心业务问题

工程细胞研究中的 DNA、RNA、蛋白组、代谢组和发酵过程数据通常由不同实验批次、仪器和人员产生。若文件、样本、培养条件、菌株与参考版本不能被可靠关联，后续多组学整合、遗传关联和模型预测就无法被复核。

本模块解决以下问题：

1. 让用户按样本登记实验文件，而不是只上传一批无归属的文件。
2. 让 DNA/RNA 参考基因组与注释、蛋白搜索库、代谢组参考资料按菌株与版本独立维护，避免每个任务重复上传或误用。
3. 在分析启动前固化“本次任务实际使用了什么”，使结果可以追溯至样本、文件和资料版本。
4. 让任务审批、补充、运行、交付和结果复核有明确状态和责任人。
5. 将复杂生信流程以“输入—处理方式—输出”的业务语言呈现，不要求普通用户理解脚本或服务器环境。

### 2.2 端到端业务闭环

```text
创建任务
  → 填写研究问题与预期交付
  → 维护组学参考资料（如尚无适用版本）
  → 按样本登记 DNA / RNA / 蛋白组 / 代谢组实验文件
  → 生成样本关联清单和任务输入快照
  → 提交数据审核
  → 审核通过后冻结输入并生成可运行模块
  → 模块化运行、逐步输出文件与图件
  → 结果复核、工程设计与发酵/湿实验验证
  → 验证结论回写工程细胞项目知识网络，进入下一轮 DBTL
```

“数据审核通过”只表示任务登记信息满足进入分析的条件，不等于已得到生物学结论。QTL/GWAS、模型模拟和预测输出都属于可复核证据，仍需领域专家和后续实验验证。

## 3. 角色与职责

| 角色 | 主要职责 | 可执行动作 | 不应承担的动作 |
| --- | --- | --- | --- |
| 任务创建人 / 研究人员 | 定义研究问题，登记样本、实验文件与培养条件，选择已维护参考资料 | 新建、编辑草稿/待补充/待审核任务，提交审核，查看任务和下载结果 | 配置服务器环境、直接修改已冻结运行输入、替代审核结论 |
| 数据管理员 | 确认文件、样本映射、实验条件和资料绑定可追溯 | 审核通过、退回补充并填写意见 | 代替研究人员编造样本关系或实验条件 |
| 生物信息人员 | 发布参数化工作流与组学参考资料版本，处理异常数据条件 | 维护流程/参数、协助判定模块适用性、解释运行异常 | 将复现包中的固定样本写入正常用户任务 |
| 领域专家 / 工程师 | 复核候选关联、模型推断和工程建议，发起下一轮验证 | 结果复核、工程设计、验证反馈 | 仅凭自动状态直接发布因果或生产结论 |

原型以“当前用户为数据管理员”展示审核按钮；正式系统应由角色、项目权限和数据资产权限共同控制。

## 5. F01 分析任务列表

### 5.1 业务定位

任务列表是任务的统一入口，不把“进度页”作为独立页面。所有状态均通过“查看”进入同一任务详情页；详情页会依据状态展示等待审核、待补充、运行过程或已交付结果。

### 5.2 列表字段

| 字段 | 含义 | 来源 / 生成规则 |
| --- | --- | --- |
| 任务编号 / 名称 | 任务唯一标识及研究人员命名 | 系统编号 + 创建人输入 |
| 研究对象范围 | 参与本任务的物种、菌株或样本范围 | 由已登记样本及绑定的组学参考资料汇总 |
| 目标产物 | 如赖氨酸、目标表型；可以为空 | 创建人输入 |
| 分析问题 / 预期交付 | 希望比较、解释或预测的问题及交付类型 | 创建人输入 |
| 数据登记 | 样本、组学文件、培养条件与参考资料登记情况 | 系统汇总 |
| 状态 | 当前所处业务状态 | 状态机 |
| 更新时间 | 最近创建、保存、审核或运行事件时间 | 系统事件时间 |
| 操作 | 对当前任务的可用动作 | 见下一节 |

### 5.3 列表操作规则

- 所有任务：`查看`、`删除`。
- `待数据审核`任务：数据管理员额外看到`审核`。
- 编辑入口不放在列表，避免操作列冗长；创建人进入任务详情后编辑。
- 不设置独立“查看进度”按钮。运行状态、已完成步骤、结果和后续等待项均在统一详情页中展示。
- 删除只适用于任务记录；正式系统应二次确认并按数据留存策略决定是逻辑删除、撤销任务还是归档。原型仅模拟交互。

### 5.4 筛选与统计

原型提供任务关键词搜索、状态筛选和重置入口，并以概览卡展示任务总数、运行中、待数据审核、已完成等统计。正式系统的统计应从服务端任务状态聚合，不能依赖前端示例行数。

## 6. F02 新建与编辑分析任务

### 6.1 设计原则

新建和编辑必须复用同一套字段与登记逻辑。编辑不应另建一套简化表单，否则会出现字段不一致、样本关系丢失或用户无法理解修改范围的问题。

原型采用两步：

1. **填写基础信息**：描述“为什么分析、希望得到什么”。
2. **登记实验文件与样本**：描述“这次实际分析哪些样本、哪些文件、采用哪套参考资料”。

提交审核是动作，不单独要求用户配置计算环境、脚本或服务器。

### 6.2 第一步：基础信息

| 字段 | 必填 | 说明 | 业务规则 |
| --- | --- | --- | --- |
| 分析任务名称 | 是 | 对本次任务的可读命名 | 由创建人填写，不使用固定下拉选项 |
| 研究对象范围 | 否（系统生成） | 参与的物种、菌株和样本范围 | 根据下一步的样本与参考资料自动汇总，支持多个菌株 |
| 目标产物或表型 | 否 | 如 L-赖氨酸、耐受性、产量、过程表现 | 无明确目标产物时可以留空 |
| 分析问题与预期交付 | 是 | 希望比较/解释的问题、结果类型和复核用途 | 应描述业务问题，不要求填写工具、脚本或服务器路径 |

不设置“工程细胞项目”或“分析目的”的强制下拉框。若后续需要关联项目，应通过项目上下文或可搜索关联选择实现，不应以示例项目替代用户输入。

### 6.3 编辑规则

| 编辑前状态 | 是否可编辑 | 保存后的状态 | 后续动作 |
| --- | --- | --- | --- |
| 草稿 | 可以 | 草稿 | 可继续修改或提交审核 |
| 待补充 | 可以 | 待补充 | 根据审核意见补齐后重新提交审核 |
| 待数据审核 | 可以 | 草稿 | 当前待审核版本失效，必须重新提交审核，避免审核版本与编辑版本不一致 |
| 审核通过 / 运行中 / 已完成 | 不可以 | 不适用 | 保持运行输入和结果的可追溯性；如确需变更，应新建任务或复制任务 |

待审核任务保存修改后退回草稿是重要的审计规则：审核人只能审核一个确定版本，不能在审核过程中被无提示地替换输入。

## 7. F03 组学参考库

### 7.1 业务定位

组学参考资料是可复用的资料资产，不是某一个任务的临时附件。一个样本先绑定某个菌株的资料版本，再登记组学文件；后续处理统一采用该版本，保证不同样本/批次的结果可比较和可追溯。

### 7.2 资料版本字段

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| 物种 | 是 | 标识资料所属物种，如 *Escherichia coli* |
| 菌株 | 是 | 标识具体菌株，如 B36 |
| 参考资料版本 | 是 | 给资料集命名和版本化，如 `B36 reference v1.0` |
| DNAseq 参考基因组（FASTA） | 是 | DNA 读段比对、覆盖度与变异检测的参考序列 |
| DNAseq 基因组注释（GFF） | 是 | 解释基因、CDS 等基因组坐标和变异影响 |
| RNAseq 参考基因组（FASTA） | 是 | RNA 读段比对的参考序列 |
| RNAseq 基因组注释（GFF） | 是 | 表达计数时定义基因/转录本区域 |
| 蛋白搜索库（FASTA） | 否 | 将质谱谱图匹配为肽段、蛋白和蛋白丰度 |
| 代谢组参考资料 | 否 | 代谢物谱库、标准品表或注释参考，用于峰注释 |

DNAseq 与 RNAseq 在实际项目中可以采用同一基因组版本，但仍要分别登记其使用版本；这避免未来两类处理对参考序列或注释的版本要求不同而失去追溯性。

### 7.3 维护与绑定规则

1. 同一菌株可以有多个资料版本。
2. 新建任务中不重复上传资料；用户在样本登记时选择已维护版本，需要时从该入口新增。
3. 一个样本绑定一个组学参考资料版本；其内部 `host_id`、物种和菌株由系统带出，用户无需手工输入。
4. 表格中的文件名应提供字段说明 tooltip；点击文件名后提示确认下载，不设置冗余“下载”按钮。
5. 正式系统需要资料版本状态、审核记录、文件校验和、权限及废弃策略；原型只演示页面行为。

## 8. F04 样本与实验文件登记

### 8.1 核心原则：以样本为单位连续登记

一条样本记录代表一个可参与联合分析的实验样本。用户填写样本编号、选择所属菌株/参考资料、填写培养条件，再在同一记录下追加 DNA、RNA、蛋白组和代谢组文件。这样才能清楚表达“哪个文件属于哪个样本、哪个菌株、什么条件”。

每类文件均支持多选上传和逐项删除。例如双端测序会在 DNA 或 RNA 记录下出现 R1 与 R2 两个文件；蛋白组或代谢组可以有多个原始文件、技术重复或批次文件。

### 8.2 样本记录字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 样本编号 (`sample_id`) | 是 | 联合分析主键；同一编号下的四类组学文件可组成同一个联合分析单元 |
| 所属菌株 / 参考资料 | 是 | 从组学参考库选择，自动带出物种、菌株和内部 `host_id` |
| 培养条件 | 建议必填 | 如培养基、温度、生长阶段、诱导条件等；跨组学按条件关联时必须可说明 |
| DNA 双端测序文件 | 按实际数据填写 | FASTQ / FASTQ.GZ；R1 与 R2 是同一 DNA 文库的两端读段 |
| RNA 双端测序文件 | 按实际数据填写 | FASTQ / FASTQ.GZ；应补充文库类型等 RNA 实验元数据 |
| 蛋白组原始文件 | 按实际数据填写 | Thermo RAW 或 mzML；需与蛋白搜索库、酶切/修饰参数对应 |
| 代谢组原始文件 | 按实际数据填写 | RAW、仪器目录压缩包、ZIP 或 mzML；需与仪器、采集方式、批次对应 |

原型允许先登记部分组学。缺失项目不会被伪装为已完成，而是在后续提交检查和模块条件判定中体现：有些任务可以只运行 DNA/RNA 基础处理，不能运行需要跨组学配对、表型或分类标签的模块。

### 8.3 原始文件接受格式和用途

| 组学 | 常见输入格式 | 必须关联信息 | 后续基础处理产物 |
| --- | --- | --- | --- |
| DNAseq | 成对 R1/R2 FASTQ 或 FASTQ.GZ | 样本、菌株、DNA FASTA/GFF | 质控、比对、覆盖度、变异表 |
| RNAseq | 成对 R1/R2 FASTQ 或 FASTQ.GZ | 样本、文库类型、RNA FASTA/GFF | 质控、RNA 比对、基因计数、TPM/CPM |
| 蛋白组 | Thermo RAW、mzML | 样本、蛋白搜索库、酶切和修饰参数 | 谱图鉴定、肽段/蛋白定量、质控表 |
| 代谢组 | RAW、仪器目录 ZIP、mzML | 样本、仪器、采集方式、批次、代谢组参考资料 | 格式转换（如需要）、峰提取、对齐、注释表 |

### 8.4 批量导入历史数据

逐样本登记是常规入口。只有历史项目、公开数据或大量存量文件不适合逐条录入时，才使用“批量导入历史数据”。批量导入至少需要：

1. 原始文件或已入库文件资产清单；
2. 文件清单，至少说明 `sample_id`、组学类型、文件名或文件资产 ID；
3. 样本关联表，补充物种、菌株、培养条件和跨组学关系；
4. 已维护的组学参考资料版本。

系统不能只依据文件名猜测样本归属。

## 9. F05 样本关联清单与任务输入快照

### 9.1 两类系统产物

| 产物 | 一行代表什么 | 作用 |
| --- | --- | --- |
| `sample_map.tsv` | 一个联合分析样本 | 表达样本、菌株、条件、各类 assay 和跨组学关联关系 |
| `raw_manifest.tsv` | 一个实际文件 | 表达文件归属、组学类型、格式、位置、校验和和来源 |

`sample_map.tsv` 不是文件上传清单；真正的文件归属由 `raw_manifest.tsv.sample_id` 指向 `sample_map.tsv.sample_id`。

### 9.2 `sample_map.tsv` 字段说明

| 字段 | 含义 | 正常创建方式 |
| --- | --- | --- |
| `sample_id` | 联合分析样本主键 | 用户登记样本编号 |
| `host_id` | 菌株主体内部标识 | 系统从绑定的组学参考资料生成 |
| `organism` | 物种 | 参考资料记录 |
| `strain` | 菌株 | 参考资料记录 |
| `condition_label` | 培养/实验条件标签 | 样本登记 |
| `DNAseq_assay` | DNA 文件集合的 assay 标识 | 系统生成，或保留公开数据 accession |
| `RNAseq_assay` | RNA 文件集合的 assay 标识 | 系统生成，或保留公开数据 accession |
| `Proteomics_assay` | 蛋白组文件集合的 assay 标识 | 系统生成，或保留公开数据 accession |
| `Metabolomics_assay` | 代谢组文件集合的 assay 标识 | 系统生成，或保留公开数据 accession |
| `pairing_level` | 关联强度 | 同一样本默认 `same_sample`；仅在有人工确认依据时标记 `condition_matched` |
| `mapping_evidence` | 关联证据 | 正常登记为系统记录；历史/公开数据导入时保存实验记录、数据库或文献依据 |

### 9.3 提交前必须满足的检查

1. 每个文件都能关联到一个存在的 `sample_id`。
2. 每个样本都绑定有效的资料版本，并能获得物种、菌株和内部 `host_id`。
3. DNA/RNA 双端文件成对，且格式符合要求。
4. 每类 assay 至少有对应文件；需要成对的 assay 满足成对关系。
5. 跨样本按条件关联时，具有培养条件和人工确认依据。
6. 正式系统完成文件大小、校验和、存储状态和权限检查后，才生成不可变运行快照。

## 10. F06 审核、补充与状态管理

### 10.1 状态定义

| 状态 | 含义 | 创建人可做什么 | 管理员可做什么 |
| --- | --- | --- | --- |
| 草稿 | 基础信息或样本登记未完成，或待审核版本被修改 | 编辑、提交审核（完成登记后） | 无审核动作 |
| 待数据审核 | 已提交确定版本，等待审核 | 查看、编辑；保存编辑即回到草稿 | 审核通过、退回补充 |
| 待补充 | 审核人指出缺失项或关联问题 | 查看意见、编辑、重新提交审核 | 等待创建人补充 |
| 审核通过 | 登记信息已可进入运行准备 | 查看 | 触发/确认后续模块生成（正式系统按权限） |
| 运行中 | 已冻结输入，正在执行模块 | 查看运行过程和已产出结果 | 查看、处理异常（按权限） |
| 已完成 | 模块和交付检查完成 | 查看、下载、发起后续复核/验证 | 查看、归档/复核（按权限） |

### 10.2 审核通过与退回补充

审核应确认：

- 实验文件是否与样本对应；
- 样本映射、菌株、培养条件和批次是否可关联；
- 已选择的组学参考资料是否适用；
- 文件来源、权限和元数据是否达到平台准入要求；
- 任务能否生成可追溯输入快照。

退回时，审核人必须填写明确的补充意见，例如“补充样本映射中的培养条件与批次，并确认 RNA 文件与样本编号的对应关系”。创建人在详情页看到意见后进入和新建相同的两步编辑流程。保存不等于自动通过；必须点击“重新提交审核”。

## 11. F07 统一任务详情：运行过程与结果

### 11.1 页面原则

详情页不把“运行过程”“独立报告”“结果总览”拆成多个割裂入口。每个模块按以下结构连续展示：

1. **输入**：本步读取的任务输入或上一阶段产物；
2. **处理方式**：面向业务用户的中文说明；脚本和工具版本保留在运行清单，不作为主文案；
3. **输出**：结构化结果、文件和图件；文件名点击后确认下载；
4. **状态与检查数**：已完成、运行中、等待审核、等待条件或有效跳过。

仅已完成的真实示例任务展示复现结果副本。待审核、待补充和运行中任务不应提前显示复现包的固定指标或文件。

### 11.2 运行阶段与模块

| 阶段 | 模块 | 业务处理说明 | 主要输出 / 启用条件 |
| --- | --- | --- | --- |
| 01 | 四组学预处理 | 进行质量检查和清理；DNA/RNA 回贴参考序列；蛋白组将质谱信号匹配为蛋白丰度；代谢组识别并对齐质谱峰 | DNA 比对/变异，RNA 计数/TPM/CPM，蛋白定量，代谢峰表与注释 |
| 02 | M0 输入冻结与运行清单 | 检查登记文件、样本关系和资料版本是否齐全，并冻结为本次输入快照 | 输入快照、运行清单、上游冻结状态 |
| 03 | M1A 酵母遗传关联（Bloom QTL） | 寻找遗传位点与性状共同变化，并校正亲缘关系统计偏差 | 关联表、Manhattan 图、QQ 图；需基因型、表型和群体结构信息 |
| 03 | M1B 大肠杆菌泛基因组关联（EcoRef GWAS） | 比较多个菌株基因有无，并寻找与条件/性状的关联 | 泛基因组矩阵、关联结果、诊断图；需多菌株和关联条件 |
| 04 | M2A RNA 表达数量性状关联（eQTL） | 检验遗传位点与 RNA 表达关联 | cis/trans eQTL 表；需基因型、表达矩阵和协变量 |
| 04 | M2B 蛋白丰度数量性状关联（pQTL） | 形成遗传位点与蛋白丰度的关联并对照 RNA 层 | pQTL、eQTL 重叠和质控表 |
| 04 | M2C 过程/代谢性状关联 | 寻找过程或代谢性状与遗传差异的共同变化 | 关联表和重点位点；需可用性状和遗传信息 |
| 05 | M3A 共表达模块（WGCNA） | 把变化趋势相似的基因归为模块，考察模块与性状关系 | 模块归属、模块—性状关系、质控表 |
| 05 | M3B 多组学潜在因子（MOFA） | 从多组学视图中提取共同变化的潜在因子 | 因子得分、权重、方差解释和模型文件 |
| 05 | M3C 监督式多组学分类（DIABLO） | 在有明确分类目标时筛选监督式整合特征 | 需要分类标签；无标签时记录“有效跳过”，不伪造结果 |
| 06 | M4A 代谢模型模拟与质量检查（GEM/MEMOTE） | 模拟可能通量分配并审计模型结构和注释质量 | FBA/pFBA/FVA、MEMOTE 报告；需匹配 GEM 与约束条件 |
| 06 | M4B 分组交叉验证预测 | 以批次分组留出测试数据，评估未见批次预测能力 | 预测、交叉验证指标和图件；需足够过程批次和目标指标 |
| 07 | Bundle 成果包完整性与可移植性检查 | 核对结果、检查信息和交付清单是否完整、可追溯 | 模块状态、结果校验和、验收报告 |

模块不是“必然全部运行”。系统依据样本数、菌株队列、跨组学配对、表型、分类标签、模型和发酵批次等条件决定启用、等待或有效跳过。

### 11.3 已完成示例任务的真实结果边界

原型的 `MO-20260806-001` 使用真实复现结果副本展示。当前可追溯的示例事实包括：

- 预处理和扩展分析验证通过；
- 模块状态清单中 M0、M1A、M1B、M2A、M2B、M2C、M3A、M3B、M4A、M4B、Bundle 完成检查；M3C 因无监督分类标签有效跳过；
- 大肠杆菌 DNA 比对率为 99.99%；
- 知识网络为 43,581 个节点、43,601 条关系；
- MEMOTE 分数：大肠杆菌 iML1515 为 0.906，酵母模型为 0.695；
- 分组预测示例共 24 个合成发酵批次；大肠杆菌 Titer R² 为 0.861，酵母 Titer R² 为 0.973。

上述数值只用于说明原型如何呈现完成任务的结果。发酵数据为合成示例批次，不构成生产或外部验证结论。

## 12. F08 结果文件与下载

### 12.1 呈现方式

- 文件名直接出现在其所属运行步骤的“输出”行内。
- 用户点击文件名时先弹出确认提示，确认后下载。
- 图件（如 Manhattan 图、QQ 图、发酵预测图和过程轨迹图）直接嵌入所属步骤，而不是只在独立结果页中出现。
- 不再单独展示“本次结果总览”或冗余下载按钮，以免重复信息和割裂流程。

### 12.2 正式系统下载要求

正式系统的下载操作应校验：当前用户是否有项目与任务权限、结果文件是否仍可用、下载是否可审计，以及大文件是否采用受控临时链接。原型中下载链接仅连接离线结果副本，用于演示交互。

## 14. 验收要点

### 14.1 创建与编辑

- 新建和编辑看到相同的基础信息及样本登记字段。
- 一个任务可登记多个菌株；样本必须选择自己的菌株/资料版本。
- 一个样本下四类组学文件可以多选并逐项删除。
- 草稿、待补充、待数据审核均可编辑；待审核保存后必须退回草稿。
- 已运行和已完成任务没有编辑入口。

### 14.2 审核与状态

- 数据管理员只能对待数据审核任务看到审核入口。
- 退回时必须有可读的审核意见。
- 待补充任务可编辑并重新提交；重新提交后变为待数据审核。
- 列表不出现重复“查看”或独立“查看进度”。

### 14.3 详情与结果

- 任何状态均通过统一“查看”进入同一结构的详情页。
- 详情按步骤展示输入、处理方式和输出；不展示无关的服务器环境配置。
- 运行中只展示已发生步骤；未完成步骤不展示固定示例结果。
- 已完成示例任务的图件直接出现在对应步骤中。
- 点击结果文件名先确认、后下载；不设置冗余下载列或“本次结果总览”卡片。
